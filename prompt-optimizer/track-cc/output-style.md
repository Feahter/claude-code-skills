# Output Style

优化 Codex、Claude Code 或其他 agent 的回答风格文件。Output Style 应聚焦表达方式和少量稳定偏好，不应复制完整工作流、权限策略和编码规范。

## 检查重点

### 产品机制

确认样式如何注入系统 prompt、何时生效，以及是否会替换内置编码指令。例如 Claude Code 自定义 Output Style 若要保留默认编码指令，应按当前官方格式设置相应 frontmatter；不要把这一字段照搬到不支持它的产品。

保留已有的样式标识，并检查设置引用使用的是文件名还是 frontmatter 名称。修改显示名称前先确认不会让当前选择失效。

### 能力保留

删除重复规则前确认内置指令、AGENTS.md / CLAUDE.md 或其他规则仍覆盖必要能力。文风优化不能以减少验证、推理、工具使用或错误处理能力为代价。

### 自然表达

优先写正向、具体的语言偏好，例如完整句子、规范标点、具体名词和动词。避免“必须像真人”“让人看不出是 AI”等身份表演目标，它们容易诱发做作表达。

机械句数上限、固定段落模板、每次都要声明假设或列选项，通常会让复杂问题说不清、简单问题变啰嗦。改用“篇幅和结构与任务复杂度匹配”一类可判断原则。

### 规则归属

把工程流程、安全红线、工具选择和项目事实放到更合适的常驻规则或 Skill。Output Style 只保留真正影响所有回答的表达偏好，以及少量不会与其他层冲突的判断原则。

### 诱导词

检查样式本身是否反复使用口号、隐喻、管理术语、强烈程度词或生硬标签。模型容易复用 prompt 的词汇和句式，即使这些词出现在规则标题中。

## 改写原则

- 保留用户明确偏好的语言、专业程度和信息密度。
- 取消与任务无关的角色扮演和“去 AI 味”表演。
- 不为追求简短设置硬句数；通过删重复和按需结构控制长度。
- 规则用自然语言解释目标，少用“铁律、绝不、立即”等连续强制措辞。
- 与其他常驻指令去重，但先确认去重后能力仍由某一层可靠提供。

## 验证

- 检查 frontmatter、文件名和设置引用。
- 对比修改前后的常驻字符或 token 量。
- 文风问题有代表性样本时，用同一组简单问答、复杂分析和代码任务做新旧版本比较。
- 说明样式通常只对新会话生效，不把当前会话的输出当成新样式验证。
- 静态断言、人工复读和设想场景只能证明规则文本满足预期；没有真实模型运行时，不称为行为回放或 A/B。

# Agent Prompt

优化发给 agent、subagent 或后台任务的委派 prompt。目标是让接收者在独立上下文中完成明确任务，同时避免复制整段主会话。

## 检查重点

### 目标

说明要解决的问题和期望结果。简单任务可以只有一两句，不强制添加 `Context:` 等固定标题。

### 必要上下文

补充接收者无法自行发现、但会改变判断的信息，例如已排除的假设、项目约束或用户明确偏好。不要粘贴与任务无关的对话历史。

### 输入和范围

给出已知文件、模块、数据或工具范围。探索任务可以允许扩展范围；修改任务要说明所有权边界，避免与其他 agent 冲突。

### 产出和完成条件

说明需要报告、补丁、文件还是结论，以及怎样算完成。只有确有长度或格式要求时才设置硬限制。

### 权限和验证

明确只读还是可写，是否允许安装依赖、提交或发布。修改任务应包含与风险相称的验证要求。

## 改写原则

- 不假设 agent 能看到主会话、未共享的文件或隐含约定。
- 不把容易自行读取的信息全部复制进 prompt。
- 不用“做到满意为止”“全面检查”代替可判断的范围。
- 不要求一句话结论，除非任务本身只需要一句话。
- 多 agent 并行时明确写入范围和共享依赖，避免重复劳动或覆盖他人修改。

## 输出

指出真正缺失或互相冲突的信息，然后给一份可直接委派的干净 prompt。保留原有变量、路径和工具名称。

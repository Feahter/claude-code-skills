# AGENTS.md / CLAUDE.md

优化用户级、项目级或目录级常驻指令，以及它们引用的规则文件。

## 检查重点

### 作用域和优先级

确认每条规则应该作用于所有项目、当前项目还是某个子目录。不同层级出现冲突时，以产品的实际优先级和项目约定为准，不凭文件名猜测。

### 常驻内容和按需内容

只把每轮都需要的偏好、路由和红线留在入口文件。语言、框架、工具或任务类型专属规则应按产品支持的方式拆到按需文件或 Skill，并在入口提供清楚的触发路径。

不要套用固定行数阈值判断“必然截断”。应结合当前产品机制、实际注入内容和上下文成本判断。

### 可执行性

把“高质量”“遵循最佳实践”等口号改成模型能执行和验证的行为。具体规则也要留有与风险相称的判断空间，避免为所有情况设置同一硬阈值。

### 冲突和重复

检查同一规则是否在用户级、项目级、Output Style、Skill 和 hook 中重复。重复不会自动增强执行，反而增加 token 和冲突概率。

### 强调和文风

只给真正不可违反的安全或数据红线使用强制措辞。大量 `MUST`、`NEVER`、感叹号和口号会掩盖优先级，也容易把回答带成规章体。

## 改写原则

- 保留项目特有事实、命令、路径和约束。
- 通用能力说明不必重复内置系统指令。
- 禁止项只在能阻止具体高概率错误时添加，不要求每条规则都有正反配对。
- 路由引用必须指向实际存在、大小写正确的文件。
- 用户要求落盘时同步检查相关层级，避免只改一个副本。

## 输出

优先报告冲突、失效引用、常驻 token 浪费和会改变行为的模糊规则。改写较大时可给建议结构；已修改文件时说明移动或删除了哪些规则及验证结果。

# 左移：需求与设计评审的质疑

适用：还没有代码，只有需求文档 / PRD / 设计方案 / 接口设计。

这个阶段的产出不是测试，是**问题清单**。一个在需求阶段问出来的边界，比上线后修它便宜两个数量级——这是「预防优于发现」唯一能落地的地方。

**证据等级注意**：此阶段唯一证据是需求文本，属 `evidence-discipline.md` 里的中等强度，**优先级封顶 P1**。除非需求明确写了会触碰不可逆资金 / 权限 / 数据完整性，那时可按后果基线判 P0。

## 质疑清单

逐条对着需求问。**每条都要落成「已明确 / 需澄清 / 记录假设继续」三态之一**，不许沉默跳过。

### 边界与规模

- 数量边界：最多多少条、最少多少条、0 条时什么样
- 长度与大小：文本上限、文件大小、批量上限
- 时间范围：可选到多久之前 / 之后，跨年跨月怎么算
- 并发上限：同时多少人操作同一对象
- 频率：能不能连点，有没有冷却

### 状态与流程完整性

- 异常流写了吗（需求最常见的缺失就是只写 happy path）
- 中断怎么办：填一半关掉、支付跳走没回来、上传中断网
- 超时怎么办：外部依赖不响应时，用户看到什么
- 重复操作：重复提交、重复领取、重复审批
- 撤销与回退：做错了能不能改、能不能撤，撤销后数据什么状态
- 状态穷举：所有状态与合法转换列全了吗，有没有互斥状态

### 权限与可见性

- 谁能做这件事，谁不能
- 跨租户 / 跨组织的可见边界
- 权限变更后，进行中的流程怎么处理
- 「看得到但点不了」和「看不到」哪种，有区别

### 数据

- 生命周期：创建后能改哪些字段、能删吗、删了级联影响什么
- 唯一性：什么算重复（大小写、空格、软删除的算不算）
- 精度：金额小数位、数量单位、汇率与换算规则
- 时区：按谁的时区算「今天」
- 老数据：这个新规则对历史数据生效吗，不生效的话怎么区分

### 一致性与时序

- 能接受最终一致吗，窗口多长算可接受
- 多个系统的数据谁是权威源
- 用户操作后要不要立即可见（读己之写）

### 可观测与验收

- 出问题了怎么发现（有没有要求监控 / 告警 / 埋点）
- **验收标准是可判定的吗**——这是最重要的一问。需求里写「体验流畅」「性能良好」而没有阈值，等于没有验收标准
- 灰度与回滚：出问题怎么关掉

### 兼容与迁移

- 老客户端 / 老版本 API 怎么办
- 需要数据迁移吗，迁移期间双写还是停机
- 有没有依赖方需要同步改

### 隐含假设

需求里的「用户会先……」「一般情况下……」「正常来说……」——每一处都是假设。逐个问：**不成立时会怎样**。

## 可测试性前置

需求阶段就要问出来的可测试性要求，等到写测试时才发现就晚了：

| 要问 | 为什么 |
|---|---|
| 关键状态有没有可观察出口 | 否则只能靠 UI 间接推断，或者根本验不了 |
| 时间相关逻辑能不能注入时间 | 否则过期、超时、跨天类场景测不了 |
| 能不能构造测试数据（含异常形态） | 否则边界场景只能纸上谈兵 |
| 外部依赖有没有 sandbox / 可 mock | 否则相关路径只能 `monitor` |
| 关键副作用能不能计数 | 否则幂等、重复类判据全部失效 |

这些是**给设计的输入**，不是给测试的备注。写成 `testability_gap` 并配 `design-fix` 处置，在开发开工前提出来。

## 产物

除了标准策略包，这个场景额外输出两部分：

**澄清清单**（按阻塞级别排序）：

| 级别 | 含义 |
|---|---|
| **阻塞** | 不澄清没法开发，会返工。（例：撤销后金额怎么处理没定） |
| **可并行** | 可以边做边定，但要在提测前定。（例：文案与提示语） |
| **记录假设** | 按最合理的假设继续，写明假设内容与谁来确认。（例：假定按 UTC+8 计算自然日） |

**假设台账**：每条「记录假设继续」的都要落台账，写清假设内容 + 如果假设错了影响什么。这份台账是后面代码阶段风险分诊的输入——**假设错了的地方就是最该测的地方**。

## 反模式

| 反模式 | 为什么不行 |
|---|---|
| 把质疑清单写成「建议完善需求文档」 | 不可执行。要指到具体哪一条哪一处缺什么 |
| 一次抛 40 个问题 | 会被整体忽略。按阻塞级别排，先给阻塞项 |
| 用通用清单逐条念一遍 | 需求里明确写了的不要再问，那是没读文档 |
| 只质疑不给建议 | 每条阻塞项给出你认为最合理的默认答案，让对方确认比让对方从零想更快 |
| 在这个阶段设计具体测试用例 | 用例是代码阶段的事，现在写的会被需求变更冲掉 |

# 失效模式：AI / LLM 系统

适用：LLM 调用、prompt 变更、RAG、智能体与工具调用、模型或模型版本切换。

这类系统的根本区别：**输出是概率性的，等值断言基本失效**。所以判据要换形态（属性、变形关系、评估集基线），不是放弃判据。

## 失效模式清单

### 输出可用性

- **格式违约**：要求 JSON 却输出带解释的散文；JSON 里多了 markdown 代码围栏；字段缺失或类型不符
- **schema 漂移**：结构大体对但枚举值超出约定集合
- **截断**：达到 max_tokens 中途断掉，产出半个 JSON
- **语言漂移**：要求中文输出但混入英文，或反之
- **长度失控**：要求一句话给了三段

### 事实性

- **幻觉事实**：编造数字、日期、人名、引用来源
- **幻觉接口**：编造不存在的 API / 字段 / 函数名（在代码类任务里最高发）
- **引用与内容不符**：给了来源链接，但链接内容不支持该结论
- **过时信息当前值**：把训练时的旧值当当前值说（版本号、价格、配置项）

### RAG 特有

- **召回失败仍强答**：检索没命中，模型用先验知识硬答，且语气一样自信
- **检索到无关内容被采纳**：相似度高但语义无关
- **分块切断关键信息**：答案跨块被切开，只召回半截
- **权限泄露**：检索层没做权限过滤，答案里带出用户无权看的内容（这是数据泄露，P0）
- **引用编号错位**：内容对但引用指向了别的块

### 提示注入与越界

- **直接注入**：用户输入里的「忽略之前的指令」被执行
- **间接注入**：模型读取的文档 / 网页 / 工具返回值里含指令并被执行（这是最容易被忽略的入口）
- **越权行动**：智能体调用了超出本次授权范围的工具
- **该拒未拒 / 不该拒却拒**：安全边界两侧都要验
- **敏感数据外泄**：prompt 里带了 PII 或密钥，出现在输出或日志里

### 工具调用与智能体

- **幻觉工具名 / 参数**：调用不存在的工具，或参数类型错
- **该调不调 / 不该调却调**：能力边界判断错
- **循环调用**：反复调同一工具不收敛
- **副作用不可逆**：智能体执行了写操作（删数据、发消息）且无确认环节
- **错误处理缺失**：工具报错后模型编造成功结果继续往下走

### 稳定性与成本

- **同输入结果抖动**：temperature > 0 时不可复现，同一测试时红时绿
- **上下文污染**：多轮对话里早期错误结论被后续引用
- **上下文超限**：长对话丢掉系统提示或关键约束
- **token 与延迟失控**：输入膨胀导致成本与 P95 延迟跳变，无上限保护

### 回归（最容易漏的一类）

- **prompt 改一处，别处退化**：为修 A 场景改了 prompt，B 场景静默变差
- **模型版本切换**：换模型后既有能力退化
- **评估集过拟合**：只在评估集上好，换真实输入就掉
- **评估集泄漏**：把线上失败样例加进评估集又用它证明修好了

## 常用 oracle

**不要用等值断言**。三条可用的路：

| 判据形态 | 怎么用 | 例 |
|---|---|---|
| **属性断言** | 判输出必须满足的性质，不判具体文字 | 是合法 JSON；必含 `amount` 且为数字；引用的 doc_id 全部在检索结果集内；不含 PII 正则命中；长度在区间内 |
| **变形关系** | 输入按已知方式变化，输出应有可预测的对应关系 | 同义改写问题，关键结论不变；加入无关句子，结论不翻转；把金额单位换算，答案等价 |
| **参照评估** | 固定评估集 + 打分器，判分数不低于基线 | 50 条评估集上通过率 ≥ 上一版本 −2%（基线要版本化落盘） |

配套的硬判据（这些是确定性的，必须有）：

| 风险类型 | oracle |
|---|---|
| 提示注入 | **必须失败**：注入样本集内，越界行为发生 0 次 |
| 权限泄露 | **必须不可见**：无权用户的问答中，受限文档内容出现 0 次 |
| 工具越权 | **副作用计数**：未授权工具调用次数 == 0；写操作必须有确认记录 |
| 召回失败 | **必须拒答或降级**：检索为空时，输出走「无法回答」路径而非自由生成 |
| 成本与延迟 | **边界**：单次调用 token ≤ 上限，P95 延迟 < 阈值 |
| 循环 | **边界**：工具调用轮次 ≤ 上限 |
| 回归 | **参照评估**：全量评估集分数与基线对比，不只看新修的那条 |

**关于抖动**：验证前先把可控的不确定性关掉（temperature=0 / 固定 seed，如果模型支持）。关不掉的用「N 次采样中至少 M 次满足」的形式给判据，并把 N、M 写进义务里——不写清就是 flaky 的源头。

## 证据来源

| 要找什么 | 去哪找 |
|---|---|
| prompt 与其变更 | prompt 模板文件 + `git log`（**prompt 的变更历史就是回归风险的证据**） |
| 采样参数 | temperature / top_p / seed / max_tokens 配置 |
| 工具定义与授权 | 工具 schema、可用工具白名单、是否区分读写权限 |
| RAG 链路 | 分块策略、embedding 模型与版本、检索 top_k、**权限过滤在检索前还是检索后** |
| 输出解析 | 解析器与 schema 校验（有没有校验，校验失败怎么办） |
| 评估集与基线 | 评估集文件位置、上一版分数记录（**没有落盘的基线等于没有基线**） |
| 注入防护 | 输入清洗、系统提示的边界声明、工具返回值是否被当可信内容 |

## 可测试性阻塞信号

- **没有固定评估集** → 一切回归类结论无从谈起。这是首要 `testability_gap`，处置是 `design-fix`（先建评估集），在此之前 prompt 变更的风险只能 `accept` 或人工 `explore`
- **没有版本化的基线分数** → 只能说「这次多少分」，不能说「有没有退化」
- **temperature 不可控且无法多次采样** → 判据退化到属性断言，等值与变形关系都不可靠
- **打分器本身不可信**（用 LLM 当裁判但没验过裁判） → 分数不能作为门禁，先验裁判与人工标注的一致性
- **无法观测工具调用序列** → 越权与循环类 oracle 失效，先补调用日志
- **检索层与权限层耦合不清** → 权限泄露风险无法验证，按 P0 处理并要求 `design-fix`

**这一类最常见的诚实结论是：先建评估集，其余都免谈。** 没有评估集的 AI 系统，所谓测试只能验「不崩」，那正是最弱的 oracle。

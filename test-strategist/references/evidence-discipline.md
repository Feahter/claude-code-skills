# 证据纪律

这张卡管一件事：**让「我觉得这里危险」变成「这里危险，证据是这个」**。

没有证据纪律，风险分析会稳定退化成一种东西——把通用测试清单换个说法念一遍，听起来专业，对本项目一条都不成立。

## 三分法

任何输入材料先拆成三堆，**拆完才能开始分析**。

| 类别 | 定义 | 记录格式 |
|---|---|---|
| **事实** | 我确实读到 / 跑到的东西 | 内容 + 位置（`src/a.ts:42`、需求 §3.2、事故 INC-1041、日志片段） |
| **推断** | 从事实推出来的判断 | 结论 + 依据的是哪条事实 + 推理链一句话 |
| **未知** | 需要问人、需要跑起来、或需要看数据才能确定 | 问题 + 谁能回答 / 怎么才能知道 |

**最重要的一条：未知项不许静默转成推断。** 「这里大概是用乐观锁吧」——如果没读到代码，这是未知，不是推断。把未知当推断用，是整份分析崩掉的起点。

未知项要么去查（能查就查，别偷懒），要么留在产物里明确写出来。留着不丢人，编掉才丢人。

## 证据格式

| 输入类型 | 合格的证据引用 | 不合格 |
|---|---|---|
| 代码 | `src/order/refund.ts:84`，或函数名 + 文件路径 | 「退款逻辑里」 |
| 变更 | commit hash / diff 的具体 hunk / 改动的文件与行 | 「最近改了支付」 |
| 需求 | 文档名 + 章节号或原文引用 | 「需求里说了」 |
| 事故 | 事故编号 / 工单号 / 复盘文档链接 | 「之前出过问题」 |
| 数据 | 指标名 + 时间窗 + 数值 | 「量挺大的」 |
| 日志 | 关键字段 + 一段真实日志 | 「日志里能看到」 |

拿不到精确位置时，宁可写「读过 `src/order/` 下三个文件，未找到幂等控制，此为未找到而非确认不存在」——这是诚实的中等强度证据，比假装读到了强。

## assumption-no-evidence 怎么用

有些风险确实值得提，但手上没证据。这时候：

1. `evidence` 字段写 `assumption-no-evidence`
2. 优先级按 `risk-rubric.md` 的证据封顶降到 **最高 P2**
3. 补一句这个假设**怎么才能验证**（要读哪个文件、要问谁、要看哪个指标）

第 3 条是关键。一个带「怎么验证」的假设是有用的工作项；一个不带的就是噪音。

**滥用信号**：一份策略包里 `assumption-no-evidence` 超过一半，说明该做的是先去读代码，不是先出报告。这时候正确动作是回到证据收集，而不是把报告交出去。

## 常见失真模式

| 失真 | 长什么样 | 怎么破 |
|---|---|---|
| **清单搬运** | 六个维度、十条通用风险，换任何项目都成立 | 每条风险问：删掉项目名它还成立吗？成立就说明没落到本项目，删掉或去找证据 |
| **术语包装** | 「存在并发一致性隐患」但说不出哪两个操作会交叉 | 逼自己写出具体交叉序列：A 做了什么、B 做了什么、谁先谁后导致什么 |
| **概率幻觉** | 「这个有 30% 概率发生」 | 没有数据支撑的概率一律删掉，改成定性的触发条件描述 |
| **严重度通胀** | 什么都是 P0，因为「万一出问题就很严重」 | 走 P0 白名单，走不通就降级 |
| **未知漂移** | 分析开头是「不确定是否有重试」，结论里变成「重试会导致重复扣款」 | 产出前对照三分清单，检查每条推断的依据是否还在事实堆里 |
| **借来的历史** | 拿别的项目 / 网上案例的事故当本项目的历史高发 | 历史高发只认本仓库的 git 记录、本团队的事故记录 |

## 证据收集的常用手法

按成本从低到高，够用就停：

```bash
# 变更面：这次动了什么
git diff --stat <base>...HEAD
git log --oneline -20 -- <path>              # 变更频度证据

# 历史高发：这块出过事没有
git log --grep='hotfix\|revert\|回滚\|紧急' --oneline -- <path>

# 影响面：谁在调它（本机有 codebase-memory graph，比 grep 准）
# trace_path(function_name, direction=inbound) 查调用方
# get_architecture(aspects=['hotspots','boundaries']) 看热点与边界
```

关系与影响半径走 codebase-memory graph，符号的确切定义与全部引用走 LSP，字符串 / 配置值才用 grep。graph 是索引快照，**结论要落到「这一行危险」时先用 LSP 或 `detect_changes` 复核**——过时的边会让你把已删掉的调用当风险。

## 与门禁的关系

`scripts/validate-package.sh` 只能查到「`evidence` 字段是否为空」这种结构性问题。**它查不出证据是真是假**。

所以这张卡的大部分内容靠自律。判断自己有没有守住，用一个问题：

> 如果有人拿着这份策略包逐条去代码里对，有几条会对不上？

答案不是「零」的时候，别交。

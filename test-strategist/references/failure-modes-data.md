# 失效模式：数据一致性与持久化

适用：数据库 schema / 事务 / 迁移 / 对账 / 数据生命周期的变更。**这一类失效大多不可逆**，按 `risk-rubric.md` 通常起步 P0/P1。

## 失效模式清单

### 事务

- **部分提交**：多个写操作不在同一事务里，前面成功后面失败，留下半成品状态
- **事务边界跨了远程调用**：事务里发 HTTP / MQ，远程成功但本地回滚（或反过来）
- **隔离级别不足**：读到未提交 / 同一事务内两次读不一致 / 幻读导致唯一性校验失效
- **先查后写的竞态**：`SELECT 判断不存在 → INSERT`，两个请求都通过检查（唯一约束是最后防线，有没有）
- **长事务**：锁持有过久，高并发下超时雪崩
- **回滚未覆盖副作用**：数据库回滚了，但已经发出的消息 / 已写的缓存 / 已上传的文件没回滚

### 迁移与变更

- **加非空字段无默认值**：老数据无法通过校验，写入直接失败
- **回填期间双写不一致**：新旧字段并存期，读的是旧的写的是新的
- **删字段前未确认无读方**：仍有代码在读，上线即 500
- **改字段类型丢精度**：`decimal` 改 `float`、`bigint` 改 `int` 溢出、字符集变更导致截断
- **大表 DDL 锁表**：迁移本身造成不可用
- **迁移不可回滚**：写了 up 没写 down，或 down 会丢数据
- **索引变更**：加唯一索引时存量数据已有重复；删索引导致慢查询

### 一致性

- **跨服务最终一致的窗口**：窗口期内业务读到不一致状态，是否可接受
- **对账差异**：两套统计口径不一致（如订单表合计 ≠ 流水表合计）
- **软删除与唯一约束冲突**：删掉再新建同名，唯一索引没算 `deleted_at`
- **级联删除误删**：删主表带走了不该删的子表数据
- **重复消费导致重复写**：消息重投 + 无幂等 = 数据翻倍

### 精度与语义

- **金额用浮点**：任何金额字段是 float / double 都是缺陷，不是风险
- **时区**：存本地时间无时区标识；跨时区统计错位；夏令时
- **NULL 与空串**：业务上区分「未填」和「填了空」时，存储层是否区分
- **枚举值与代码不同步**：库里有代码里没有的枚举值
- **JS 精度**：`bigint` 主键经 JSON 传到前端超 `2^53` 被截断

### 数据生命周期

- 归档与清理误删活跃数据；保留期与合规要求不符
- 冷热分离后查询漏掉冷数据
- 备份可用性（从未验证过能恢复）

## 常用 oracle

| 风险类型 | oracle 取向 |
|---|---|
| 事务原子性 | **不变量**：注入中途失败后，所有相关表处于操作前状态，无半成品 |
| 对账 / 转移 | **守恒**：操作前后总额相等；两套口径的合计相等 |
| 先查后写竞态 | **副作用计数** + **必须失败**：并发 N 次只成功 1 次，其余被唯一约束拒绝 |
| 迁移正确性 | **往返 / 参照对照**：迁移前后对同一批样本的关键字段逐条比对；`down` 后数据回到原状 |
| 精度 | **参照对照**：与 decimal 精确计算结果逐位比对，不接受近似 |
| 软删除唯一性 | **必须成功 + 必须失败** 配对：删后可新建同名；未删时新建同名必须被拒 |
| 级联影响 | **不变量**：删主记录后，不该受影响的表行数不变 |
| 时区 | **往返**：写入再读出，转成目标时区后等于预期时刻 |

## 证据来源

| 要找什么 | 去哪找 |
|---|---|
| 表结构与约束 | migration 文件、schema.prisma / entity 定义、`SHOW CREATE TABLE` |
| 事务边界 | 事务注解 / `transaction(` 调用点、service 层方法的调用链 |
| 隔离级别 | 数据库配置、连接串参数、显式 `SET TRANSACTION` |
| 幂等与唯一性 | 唯一索引定义、幂等键表 |
| 迁移可逆性 | migration 的 down 方法是否存在且真能逆转 |
| 金额与精度 | 字段类型（grep `float`/`double` + 金额相关字段名） |
| 变更影响 | migration 的 `git log`；受影响表被哪些 repository 读写 |

**最高性价比的一次检索**：grep 金额 / 数量类字段是否用了浮点类型，以及新增 migration 是否有对应 down。这两条几乎每次都能查出真问题或真确认。

## 可测试性阻塞信号

- **测试无独立数据库 / 无法回滚**：数据类断言互相污染，结论不可信 → 先解决隔离，否则相关义务只能标 `explore`
- **造不出历史数据形态**：迁移正确性无法验证（老数据的脏形态才是迁移会炸的地方）→ 要求从生产脱敏取样，或明确写进不覆盖范围
- **无法注入中途失败**：事务原子性无法验证 → 需要可注入的失败点，属 `design-fix`
- **生产与测试库 schema 不一致**：任何 schema 相关结论都不可迁移，必须显式声明这个前提
- **数据量差异**：测试库千条、生产库千万条，锁表与慢查询类风险测不出来 → 处置改 `monitor`

# 专项质量维度

适用：性能、安全、可访问性、兼容性这四类非功能维度的风险识别与验证义务。

**边界声明**：本卡只做风险识别与判据设计。深度实现交给现有资产——性能优化实现走 `performance-optimizer`，前端契约守护（bundle 大小、a11y 门禁、性能预算）走 `playbook/references/contracts.md`。这里不重复它们的内容。

## 性能

### 风险识别信号

从代码就能看出来的，不必等压测：

- **N+1 查询**：循环里发查询 / 循环里 await
- **无分页的列表接口**：随数据增长必然塌陷
- **缺索引的查询条件**：新加的 where 字段有没有索引
- **无超时的外部调用**：一个慢下游拖垮整个链路
- **同步阻塞**：在请求路径里做耗时计算 / 大文件读写
- **大 payload**：一次返回几 MB，或返回了前端用不到的整棵树
- **无限流**：批量接口不限制数组长度
- **前端**：首屏加载大 chunk、长列表不虚拟化、频繁重渲染、大图未压缩

本机有 codebase-memory 的复杂度信号可直接查：`transitive_loop_depth >= 3`、`linear_scan_in_loop >= 1`（循环内做 find/includes 的隐藏 O(n²)）、`alloc_in_loop`。这是**有证据的性能风险**，比「感觉这里可能慢」强得多。

### oracle

| 判什么 | 形态 |
|---|---|
| 响应时间 | **边界**：P95 < 阈值。阈值必须有来源（SLA / 现有基线 / 用户可感知门槛），拍脑袋的阈值不算 |
| 查询次数 | **边界**：单请求 SQL 条数 ≤ N（这条比响应时间更稳定，不受机器性能影响，优先用它） |
| payload | **边界**：响应体大小 ≤ N KB |
| 复杂度 | **单调性**：数据量翻倍，耗时增长不超过线性的 k 倍（验的是复杂度量级，不是绝对值） |
| 资源 | **不变量**：连接数 / 内存不随请求数单调上涨（无泄漏） |

**优先选与环境无关的判据**（查询条数、payload 大小、复杂度量级），它们在 CI 上稳定；绝对耗时阈值放到专门的压测环境，别塞进功能测试里当门禁——那是 flaky 的主要来源之一。

### 阻塞信号

测试环境数据量与生产差几个数量级时，性能结论不可迁移。此时处置改 `monitor`，并在不覆盖范围写明。

## 安全

### 风险识别信号

本 skill 覆盖的是**开发过程中能识别的常规安全风险**，不做渗透测试与漏洞挖掘：

- **鉴权缺失或顺序错**：新接口没挂中间件；先查数据后判权限
- **越权（IDOR）**：资源 id 可猜且无归属校验（这是最高发的一类）
- **输入未校验**：SQL / 命令 / 模板注入面、路径穿越、SSRF（用户可控 URL 被服务端请求）
- **敏感数据处理**：密钥硬编码、PII 进日志、错误信息带堆栈或 SQL、响应体带多余敏感字段
- **传输与存储**：密码明文或弱哈希、token 放 localStorage、Cookie 缺 HttpOnly/Secure/SameSite
- **前端**：`innerHTML`/`dangerouslySetInnerHTML` 接用户内容、`postMessage` 不校验 origin、CSRF 防护缺失
- **依赖**：已知漏洞依赖、锁文件未提交

### oracle

安全类判据几乎都是 **必须失败** 形态：

| 判什么 | oracle |
|---|---|
| 越权 | 非授权主体请求返回 403，且响应体不含目标数据（**200 + 空数据不算通过**——它泄露了资源存在性） |
| 注入 | 恶意载荷不产生副作用，且不出现在响应中被解释执行 |
| 敏感数据 | **属性断言**：响应体与日志中，敏感字段正则命中数 == 0 |
| 鉴权覆盖 | **不变量**：所有非白名单路由都要求认证（这条可以用脚本枚举路由自动验，性价比极高） |

最后一条特别推荐：枚举路由表逐个发无凭证请求，断言全部被拒。一次投入，长期防「新接口忘挂鉴权」。

### 阻塞信号

测试环境鉴权配置与生产不同时，越权类结论不可迁移，必须显式声明。涉及真实密钥或生产数据的验证不要在本地做。

## 可访问性

### 风险识别信号

- 交互节点非语义元素（`div onClick`）、无可访问名
- 键盘不可达；弹窗打开后焦点未收拢（焦点跑到背景内容）
- 仅靠颜色传达状态；对比度不足
- 表单控件无关联 label；错误提示未与控件关联
- 动态内容更新无 live region 提示

**a11y 与可测试性同源**：缺语义锚点既让屏幕阅读器读不懂，也让 E2E 只能退到 `nth-child`。修一处治两病，所以 a11y 缺口值得作为 `design-fix` 提出，而不只是 `test`。

### oracle

| 判什么 | oracle |
|---|---|
| 自动可查项 | **边界**：axe 规则违规数 == 0（或不高于基线） |
| 键盘可达 | **必须成功**：仅用键盘能完成核心流程 |
| 焦点管理 | **不变量**：弹窗开启期间焦点不离开弹窗 |
| 可访问名 | **属性断言**：交互元素均有非空 accessible name |

自动化工具只能覆盖一部分，剩下的（语义是否合理、提示是否有意义）需要人工 `explore`，别假装自动化能全覆盖。

## 兼容性

### 风险识别信号

- 用了较新的浏览器 API 而无降级或 polyfill
- 视口极端宽度、系统字号放大、深浅色模式
- 触屏：hover 才出现的操作在触屏不可达；点击区域过小
- API 版本兼容：老客户端调新接口
- 依赖运行时版本（Node / 浏览器最低版本）与声明不符

### oracle

| 判什么 | oracle |
|---|---|
| API 降级 | **必须成功**：在不支持该 API 的环境下核心流程仍可完成 |
| 视口 | **属性断言**：目标视口集下无横向溢出、关键元素可见可点 |
| 版本兼容 | **参照对照**：老版本请求样本在新服务上行为不变 |

兼容矩阵要有**来源**（真实用户设备与浏览器分布数据），不要凭想象列一堆设备。没有数据就说明没有数据，按最保守的两三档处理。

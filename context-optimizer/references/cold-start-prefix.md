# 第一步方法卡：冷启动与平均前缀

## 1. 先把概念钉住

- **前缀**：每次调用模型时，用户本轮输入之前的全部内容。包括系统提示、工具定义、常驻规则或记忆、检索注入、历史消息。
- **固定前缀**：每个会话首轮都一样的部分，即系统提示、工具定义和常驻规则。
- **平均前缀**：所有调用的前缀 token 均值。它由固定前缀和历史增长共同决定，长会话会把它拉高。
- **冷启动**：会话或用户在没有历史时的头几轮。常见表现是首轮答非所问、反复追问才进入状态、需要多轮才能拿到首个有效产出。

先确认用户口中的"冷启动"指的是哪一种：首轮延迟和成本（缓存还没建立）、首轮效果（缺上下文导致答偏），还是新用户的上手轮次。三者的病灶和动作完全不同，混在一起会开错药。

## 2. 现状要报告的内容

| 项 | 怎么得到 | 缺失时 |
|---|---|---|
| 固定前缀各组成部分的 token 数 | A 类：用户提供，或按字符数推算（英文约 4 字符/token，中文约 1.5 到 2 字符/token，标"推算"）。B 类：见 measure-local.md | 用推算值，注明误差可能在 ±30% |
| 平均前缀与长会话占比 | A 类：用户提供。B 类：jsonl 汇总 | 写明缺失，只对固定前缀下结论 |
| 缓存命中率 | API usage 的 cache_read 与总输入之比 | 写明缺失。不能确定缓存是否生效时，第一条建议就是先量 |
| 前缀稳定性 | 检查前缀里有没有每次都变的内容 | 这项能从提示词文本直接看出，不缺数据 |
| 冷启动指标 | 用户提供 | 写明缺失，冷启动部分改为只列出风险点和需要埋的指标 |

## 3. 前缀病灶清单

每一项都写清判据，命中后才进入优化清单。

| 病灶 | 判据 | 典型动作 | 常见风险 |
|---|---|---|---|
| 前缀不稳定，缓存反复失效 | 时间戳、请求 ID、随机示例、用户名等动态内容出现在静态内容之前；工具列表顺序每次不同；同一段系统提示有多个版本轮换 | 静态内容放前、动态内容放后；动态值移到最后一条用户消息；固定工具顺序。缓存断点和最小可缓存长度随模型不同，查 `claude-api` skill 或官方文档后再定 | 低。注意别把影响行为的动态信息挪到模型看不到的位置 |
| 工具定义过多 | 工具数量多、近期调用次数为零或极少，或者 schema 描述冗长 | 移除零调用工具；改为按需加载（deferred 或路由型工具）；压缩 schema 描述里重复的说明 | 中。删掉低频但关键的工具会在偶发场景失效，先看调用统计 |
| 常驻了按需内容 | 只在某类任务才用到的长篇说明（某个领域的规范、某个工具的完整手册）每轮都在 | 改为路由表加按需读取，常驻里只留一行"何时读哪个文件" | 中。路由描述写得不准会导致该读时没读 |
| 检索注入过量 | RAG 默认塞 top-k 全文，没有相关度阈值；同一文档在多轮里重复注入 | 加阈值、截断到相关段落、多轮去重 | 中。召回不足会降低准确率，需要对比评测 |
| 历史无限增长 | 会话没有轮数或 token 上限，也没有摘要机制；大工具输出原样留在历史里 | 工具输出先裁剪再入历史；超过阈值时做摘要或开新会话；在阶段边界清空 | 中。摘要会丢细节，关键决策要显式保留 |
| 示例占比过高 | few-shot 示例超过前缀的三分之一，或者多个示例教的是同一件事 | 留下覆盖不同边界的最少示例，同类示例只保留一个 | 中。输出格式可能漂移，需要回放验证 |

## 4. 冷启动病灶清单

| 病灶 | 判据 | 典型动作 |
|---|---|---|
| 首轮缺关键上下文 | 首轮常见反问集中在同几项信息上（用户身份、项目、目标） | 把这几项在会话开始时自动注入，或者在首轮提示里要求一次性收齐，不要逐项追问 |
| 首轮目标不明 | 系统提示里没有说清首轮该产出什么，模型先寒暄或先列一堆选项 | 写明首轮的默认动作和产出形式 |
| 默认值缺失 | 模型在可以合理默认的地方停下来问 | 给出默认值，并说明什么情况下才需要问 |
| 冷启动和稳态共用一套长提示 | 首轮用不到的大量稳态规则也在首轮 | 分阶段加载：首轮只放入门所需内容，进入具体任务后再加载对应部分 |
| 首轮延迟高 | 首轮的缓存写入很大 | 先确认是否只是正常的首次建缓存。确实偏大时再压缩固定前缀，或在会话开始前预热缓存 |

## 5. 不该做的

- 固定前缀稳定且已命中缓存时，砍它对成本的影响很小。这时如果唯一理由是省钱，就不要列为高优先级。它对注意力的影响放到第二步去评估。
- 不要为了压 token 把关键约束压成缩写或符号。省下的 token 远小于理解出错的代价。
- 不要在没有基线数据时承诺具体的百分比收益。
